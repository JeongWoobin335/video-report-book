  • no-cache를 "아예 저장하지 않는다"로 알고 있는 분이 7명 중 5명으로, 정답(2명)보다 많습니다. 오답 5명 전원이 같은 보기("디스크에 아예 저장하지 않습니다")를 골랐고, 이것은 no-store의 설명입니다. 같은 혼동이 옆 문항에도 이어져, 민감한 응답에 no-cache를 고른 분이 3명, HTML 문서에 no-store를 고른 분이 3명이었습니다. 이 소주제 정답률은 43%로 전체에서 가장 낮습니다. 강사가 "헷갈리기 쉽다"고 짚은 부분인데도 이름이 주는 인상을 이기지 못했습니다. → 이 구간에 두 지시어를 나란히 놓은 비교 표(저장 여부 / 서버 확인 여부 / 쓰는 곳: HTML vs 은행 내역)를 화면에 넣고, 신입 채널에 "no-cache = 저장하되 매번 확인, no-store = 저장 안 함" 한 줄을 먼저 공지하시길 권합니다.   • ETag가 언제 바뀌는지를 묻는 문항은 강의가 아니라 문항을 고쳐야 합니다. 점수 상위 3명(8·8·7점)이 전원 틀리고 하위 4명은 전원 맞혔습니다. 상위권 두 명이 고른 "서버가 응답을 새로 보낼 때마다"는, 강의가 "ETag가 다르면 200 OK와 새 본문·새 ETag가 온다"고 설명한 것을 떠올리면 "새 내용의 응답을 보낼 때"로도 읽힙니다. 응답자가 7명이라 단정은 어렵지만 패턴이 뚜렷합니다. → 그 보기를 "내용이 같아도 요청이 올 때마다 매번 새 값으로"처럼 분명히 틀리게 고치세요. 이 구간의 강의 보강은 필요 없어 보입니다.   • ETag가 같을 때 서버가 무엇을 돌려주는지는 절반 이상이 찍었습니다. 정답("본문 없이 304")은 7명 중 3명이고, 오답 4명은 세 보기에 2·1·1로 흩어졌습니다. 상태 코드(304/200)와 본문 유무 두 가지를 동시에 기억해야 하는데, 어느 쪽도 확실히 남지 않았습니다. 문항 자체는 모호하지 않습니다. → 이 30초 구간에 실제 요청·응답 예시(개발자 도구 네트워크 탭에서 304, 본문 크기 0)를 한 번 보여주어 비중을 키우시길 권합니다. [07:25–07:55]
