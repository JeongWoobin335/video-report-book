HTTP 캐싱 기초 (웹 성능 입문 3강)

웹 성능 입문 3강으로, HTTP 캐싱의 기본을 다룬다. 캐시가 무엇이고 왜 쓰는지에서 출발해, 서버가 `Cache-Control` 헤더로 저장본의 사용 기간을 알려주는 방법, 헷갈리기 쉬운 `no-cache`와 `no-store`의 차이, 그리고 `ETag`와 `304 Not Modified`로 저장본을 검증하는 흐름을 순서대로 설명한다. 마지막에 파일 종류별 실무 설정 팁을 주고, 다음 시간 주제로 CDN 캐시를 예고한다.

학습 목표

  • 캐시란 무엇이고 왜 쓰는지 안다. 00:20
  • Cache-Control 헤더로 캐시를 제어하는 방법을 안다. 00:20
  • ETag로 저장본이 아직 유효한지 검증하는 방법을 안다. 00:20
  • 최종 목표: 응답 헤더만 보고 그 리소스가 브라우저에서 어떻게 캐시될지 설명할 수 있다. 00:50

핵심 개념

  • 캐시(Cache) — 한 번 받아온 응답의 복사본을 가까운 곳에 저장해 두었다가, 같은 요청이 오면 서버까지 가지 않고 그 복사본을 돌려주는 것. 01:10
  • 브라우저 캐시 — 브라우저가 받은 리소스를 자기 디스크에 저장해 두고 다음부터 그것을 쓰는 것. 02:35
  • Cache-Control — 저장본을 언제까지 써도 되는지 서버가 브라우저에 알려주는 응답 헤더. 03:00
  • max-age — 이 응답을 몇 초 동안 신선한(fresh) 것으로 볼지를 초 단위로 적는 값. 강사가 "가장 중요한 값"이라고 함. 03:25
  • s-maxage — 공유 캐시(CDN, 프록시) 전용 max-age. 슬라이드에만 있음(강사는 말로 설명하지 않음). 02:58
  • ETag — 서버가 리소스 내용에 붙이는 지문 같은 값. 내용이 한 글자라도 바뀌면 ETag도 바뀐다. 06:15
  • If-None-Match — 브라우저가 기억해 둔 ETag를 담아 "내가 가진 버전이 아직 맞냐"고 서버에 묻는 요청 헤더. 07:00

내용 정리

캐시를 왜 쓰는가

  • 사용자 입장에서는 페이지가 빨리 뜬다. 01:40
  • 서버 입장에서는 요청 수가 줄어 부하와 비용이 내려간다. 01:40
  • 예시: 쇼핑몰 첫 화면의 로고 이미지는 몇 달에 한 번 바뀔까 말까 한데, 페이지를 열 때마다 서버에서 새로 받으면 낭비다. 02:05
  • 예시: 그래서 브라우저가 로고를 한 번 받으면 디스크에 저장해 두고 다음부터는 그것을 쓴다. 02:35

Cache-Control과 max-age

  • max-age 기간 동안 브라우저는 서버에 묻지 않고 저장본을 그대로 쓰며, 네트워크 요청 자체가 나가지 않는다. 03:50
  • 예시: 슬라이드의 헤더는 Cache-Control: max-age=3600. 강사는 이 경우 "하루 동안" 저장본을 쓴다고 말했다(슬라이드 표기는 1시간 — 아래 "영상 속 자료와 발언이 다른 부분" 참고). 03:50

no-cache와 no-store

지시어저장동작시각
no-cache한다쓸 때마다 서버에 아직 써도 되는지 반드시 확인04:35
no-store안 한다응답을 아예 디스크에 남기지 않음. 은행 거래 내역 같은 민감한 응답에 사용05:05
  • 주의: no-cache는 이름만 보면 "캐시하지 말라"는 뜻 같지만 아니다. 슬라이드 경고 문구도 "no-cache ≠ 캐시 안 함". 04:35
  • 주의: 강사가 "시험에도 면접에도 단골로 나오니 꼭 구분해 두라"고 강조했다 — no-cache는 매번 검증, no-store는 저장 금지. 05:35

ETag로 저장본 검증하기

  • 1단계: 첫 응답 때 서버가 200 OK와 함께 ETag(슬라이드 예: "a1b2c3")를 주고, 브라우저는 저장본과 함께 ETag를 기억해 둔다. 06:40
  • 2단계: 확인이 필요해지면 브라우저가 If-None-Match 헤더에 그 ETag를 담아 요청을 보낸다. 07:00
  • 3단계(같을 때): 서버는 본문 없이 304 Not Modified만 돌려주고, 브라우저는 저장본을 그대로 쓴다. 07:25
  • 3단계(다를 때): 서버는 200 OK와 함께 새 본문과 새 ETag를 내려준다. 07:55
  • 304 응답은 본문을 보내지 않으므로 훨씬 가볍다. 07:25

정리

  • max-age = 신선한 기간. 09:10
  • no-cache = 매번 검증, no-store = 저장 금지. 09:10
  • ETag와 304로 본문 없이 검증한다. 09:10

영상 속 자료와 발언이 다른 부분

영상에 나온 화면 자료(슬라이드, 문서, 대시보드 등)에 적힌 내용과 사람이 실제로 말한 내용이 서로 달랐던 곳입니다. 분석 오류가 아니라 영상 자체에 있는 불일치이며, 어느 쪽이 맞는지는 판단하지 않고 둘 다 적었습니다.

  • max-age=3600의 기간: 슬라이드에는 "3600초 = 1시간"으로 적혀 있으나, 강사는 "하루 동안은 서버에 묻지도 않고 저장본을 그대로 쓴다"고 말함. 03:50
