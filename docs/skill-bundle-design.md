# video-report-book — 스킬 묶음

영상(회의·교육 등)을 올리면 → 음성 전사 + 화면 읽기 → 통합 리포트 → 이해도 퀴즈 + 요약 만화.

## 스킬이란 (이 프로젝트에서)

스킬은 Claude가 그 일을 잘하도록 건네는 지식 묶음이다.

```
<skill-name>/
├── SKILL.md      언제 쓰는지 + 작업 흐름 + 왜 그렇게 하는지 (짧게)
├── references/   필요할 때만 읽는 지식 — 형식 가이드, 작성법, 좋은 예/나쁜 예
├── assets/       결과물에 그대로 쓰이는 파일 — HTML 템플릿, CSS, SVG
├── scripts/      매번 똑같이 돌아야 하는 부분만 — 추출, 병합, 검증, 렌더링, 채점
└── evals/        테스트 프롬프트와 샘플 입력
```

판단과 글쓰기는 Claude가 하고, 스크립트는 결정적인 일만 한다.
웹 서비스의 워커는 Claude Agent SDK에 이 스킬 묶음을 로드해서 돌린다 — 스킬을 고치면 서비스가 그대로 좋아진다.

## 8개 구성

| 스킬 | 하는 일 | 주된 내용물 |
|---|---|---|
| `video-ingest` | 영상 → 오디오 + 키프레임 | scripts (ffmpeg) |
| `speech-transcribe` | 오디오 → 시간 붙은 전사 | scripts + 엔진 설정·한국어 팁 |
| `screen-read` | 키프레임 → 화면 글자와 내용 | 화면 유형별 읽는 법 |
| `integrated-report` | 전사 + 화면 → 통합 리포트 | 유형별 리포트 형식, 근거 규칙, HTML 템플릿 |
| `comprehension-quiz` | 리포트 → 이해도 퀴즈 | 문항 작성법(교육용/회의용), 퀴즈 UI 템플릿 |
| `comic-recap` | 리포트 → 요약 만화 | 스토리보드·연출 가이드, 말풍선 레이아웃 |
| `quiz-grading` | 응답 → 점수 + 다시 볼 구간 | scripts |
| `video-report-pipeline` | 위를 순서대로 | 흐름만 |

## 작업 폴더

한 영상 = 한 폴더. 스킬들은 이 폴더의 파일로만 이어진다.

```
work/<이름>/
  video.mp4
  audio.wav            video-ingest
  frames/0001.jpg ...  video-ingest
  transcript.json      speech-transcribe
  screens.json         screen-read
  timeline.md          integrated-report (전사+화면을 시간순으로 합친 읽기용 문서)
  report.md            integrated-report (원본) → report.html, report.json (파생)
  quiz.json            comprehension-quiz
  comic/               comic-recap
  attempts/            quiz-grading
```

근거는 **타임스탬프**다. 리포트의 모든 항목은 `[03:02]`를 달고, 퀴즈와 만화는 리포트 항목에서 나오므로 같은 타임스탬프를 물려받는다. 그래서 오답에 "03:02부터 다시 보세요"가 가능하다.

## 진행 순서

한 스킬씩: 초안 → 테스트 프롬프트 실행 → 결과 검토 → 개선.
테스트 작업공간(`skills/<name>-workspace/`)은 스킬이 마무리되면 지운다. 남기는 것은 스킬 폴더의 `evals/`(테스트 프롬프트와 샘플 입력)와 `docs/examples/`(결과물 예시)뿐.

1. `integrated-report` ✔ 2026-09-17 — 2회 반복. 가상 입력 3종(회의, 강의, 음성만)에서 채점 기준 27/27, 스킬 없이 돌린 기준선은 20/27. 예시: `docs/examples/`. 미검증: 실제(지저분한) 전사, 1시간 넘는 영상, general 유형.
2. `comprehension-quiz` ✔ 2026-09-17 — 1회. 강의 10문항·회의 8문항, 채점 기준 22/22 (기준선 10/22). 난이도 대신 `기억`/`이해` 구분, 회의용은 점수 대신 "다시 확인하실 부분". 퀴즈 화면 동작을 브라우저에서 확인함. 미검증: general 유형, 긴 리포트.
   이후 스킬부터는 스킬 없는 기준선은 돌리지 않는다 — 스킬 있는 버전만 돌려 결과물 품질을 직접 본다.
3. `quiz-grading` ✔ 2026-09-17 — 1회. 가상 응답(강의 7명, 회의 5명)에 심어 둔 패턴(공유된 오해, 찍은 흔적, 문항 문제, 이해≪기억, 개인 부진)을 모두 짚음. 회의용은 개인 점수표 없이 "~로 알고 있는 분이 N명" + 공지 권고. 결과 페이지 렌더링을 브라우저에서 확인함. 미검증: 응답 수십 명 규모, 무응답이 섞인 경우.
4. `comic-recap` ✔ 2026-09-17 — 이미지 생성 없이 시작: SVG 캐릭터 에셋(`assets/cast.json`, `characters.js`) + 영상의 실제 화면을 컷 안 보드에 띄움. 강의·회의 각 8컷, 렌더링 확인. 그림체는 추후 재검토(에셋 교체 또는 AI 이미지 옵션 — `comic.json` 구조는 그대로 입력이 됨).
5. `video-ingest`, `speech-transcribe`, `screen-read` ✔ 2026-09-17 — 직접 만든 테스트 영상(`samples/lecture-http-caching.mp4`, 슬라이드 8장 + 한국어 TTS 4.3분)에서 키프레임 8장 정확히 추출, GPU 전사 1분 이내. 화면 읽기는 API 없이 Claude가 키프레임을 직접 봄. 화자 분리는 하지 않음.
6. `video-report-pipeline` ✔ 2026-09-17 — 순서표 + `status.py`(파일 존재로 진행 상태 판단, 오래된 결과물 표시) + `index.html`.
7. **전체 통합 테스트 ✔ 2026-09-17** — 에이전트 하나가 `samples/lecture-http-caching.mp4`만 받아 파이프라인 스킬을 따라 끝까지 진행. 약 4분 30초에 리포트(33항목)·퀴즈(10문항)·만화(8컷)·모아보기 페이지 생성, 실패한 단계 없음. 실제 음성 인식 결과("이 태그", "맥스 에이지")를 화면 표기로 바로잡았고, 강사 말실수(3600초를 "하루")는 리포트에 둘 다 기록 → 퀴즈·만화에서 제외. 브라우저에서 확인: 리포트의 타임스탬프 클릭 시 영상 이동, 만화에 실제 슬라이드 배경. 마찰 기록에서 나온 수정(전사 용어 재실행 기준, 어긋난 내용의 하류 차단 강화, 근거 대조표 중복 제거, 문항 수·기억/이해 기준 등)을 반영함.
   결과 확인: `python tools/serve.py` 후 http://127.0.0.1:8765/work/lecture-http-caching/index.html (영상 구간 이동은 Range를 지원하는 서버에서만 동작 — 파이썬 기본 http.server로는 안 됨)

8. **실제 녹화본 테스트 ✔ 2026-09-17** — Google Meet 녹화(19분, 4명, 화면 공유 없음)로 전 과정 약 7분, 실패 단계 없음. 회의록 40항목·확인 문항 7개·만화 8컷. 드러난 문제를 반영함: 본편 밖 사담 제외 규칙, 한 번만 들린 숫자·이름에 `(확인 필요)`(퀴즈·만화가 쓰지 못하게 스크립트로 차단), 참가자 타일 화면(`participants`)을 썸네일·만화 배경에서 제외하고 타임라인을 시간 기준으로 묶음, 핵심어가 뭉개졌을 때의 2차 전사 기준, 이름표만으로 발언자를 단정하지 않는 규칙, 설명형 회의의 리포트·퀴즈 지침, 스크립트 출력 UTF-8 고정, `status.py` 오탐, `ingest.py --frames-only`.

### 서비스 형태와 비용 (2026-09-18 논의)
- 목표: **웹 서비스**, 사용자 무료·키 입력 없음, 운영자 비용 0원, 운영자 PC 꺼져 있어도 동작. (플러그인 배포는 고려하지 않음)
- 확인된 사실: Claude API·OpenAI API에는 상시 무료 등급이 없다(신규 체험 크레딧뿐). 제3자 서비스가 사용자의 Claude 구독을 쓰려면 Anthropic 사전 승인이 필요하다(Agent SDK 문서). Gemini API에는 무료 등급이 있다(입력이 제품 개선에 쓰임).
- 방향: 화면은 github.io, 글쓰기는 무료 모델 API, 무거운 전처리(오디오·키프레임 추출)는 사용자 브라우저. 실행은 Claude 에이전트 대신 **코드가 단계별로 모델을 호출**(`tools/free_model_eval/run.py`가 그 뼈대) — 스킬의 지식 문서를 프롬프트로, 스킬의 검증 스크립트를 수리 루프로 그대로 쓴다.
- **무료 모델 품질 시험 (가상 샘플 2종, `gemini-3.6-flash`)**: 리포트·퀴즈·만화 모두 검증 스크립트를 첫 시도에 통과. 편당 호출 3회, 약 2만 7천 토큰, 48초. 회의 샘플은 채점 기준 대부분 충족(최종 결정일, 담당 미정, 미결, 자료·발언 불일치 기록, 이름 없는 참석자). 놓친 것: 강의에서 슬라이드에만 있던 `s-maxage`를 강사 설명처럼 쓰고 퀴즈로까지 출제, 다툼 있는 "QA 3주"를 요약·만화에 사용, 만화가 거의 모든 컷에 화면 배경(경고는 수리 루프를 타지 않음), 항목 수가 Claude보다 적음(18~19 vs 24~34). → 보완 후보: 경고도 수리 루프에 넣기, 근거 대조표로 한 번 더 검토시키는 호출 추가.
- 무료 등급의 불안정성: 시험 당시 `gemini-3.8-flash`·`3.7-flash`·`flash-latest`는 503(수요 폭주)으로 5회 재시도 모두 실패, Pro는 무료 한도 없음(429). 오픈소스 `gemma-4-31b-it`는 같은 키로 호출되나 10분 넘게 걸림. → 모델 여러 개를 차례로 시도하는 폴백이 필수.
- 미확인: 하루 무료 한도(편수), 전사(`gemini-3.5-transcribe` 모델이 목록에 있음 — 한국어 품질·한도 미시험), 무료 등급을 공개 서비스에 써도 되는지(약관), 실제(지저분한) 전사에서의 품질 — 실제 회의 전사는 제3자 정보라 무료 등급에 보내지 않았음.

### Gemini 기준 재설계 (2026-09-18 시작)
네 개 층: ① 지식(`skills/*/references/*.md` — 모델과 무관, 그대로) ② 도구(`skills/*/scripts/*.py` — 그대로) ③ **진행기 `engine/`**(신규) ④ 서비스(백엔드 API·브라우저 전처리·화면 — 예정).
- `engine/llm.py` — Gemini 호출. 모델 목록을 차례로 시도(503·429면 기다리지 않고 다음 모델), 응답한 모델을 그 실행 동안 유지, 호출별 토큰 기록. 표준 라이브러리만 사용.
- `engine/prompts/*.md` — SKILL.md에서 에이전트용 지시(스크립트 실행 등)를 빼고 규칙·형식만 남긴 프롬프트: classify, report, review, quiz, comic. 형식 가이드·작성법은 `skills/`의 references를 그대로 붙인다.
- `engine/pipeline.py` — 유형 판별(짧은 호출) → 리포트 초안 → 검증·수리(오류와 **경고** 모두 되돌려 고치게) → **검토 호출**(근거 대조표를 주고 항목별 점검: 슬라이드에만 있는 내용, 어긋난 값의 확산, 한 번만 들린 숫자, 빠진 이유·예시) → 렌더링 → 퀴즈 → 만화 → 모아보기. Claude 에이전트가 재량으로 하던 일을 코드 단계로 고정한 것.
- 결과(가상 샘플 2종): 편당 호출 5~7회, 입력 약 3만 + 출력 4천 + 사고 1만 토큰, 85~100초. 첫 시험에서 놓쳤던 것이 메워짐 — `s-maxage`를 "슬라이드에만 있음"으로 표시하고 퀴즈에서 제외, 요약·퀴즈·만화에서 다툼 있는 "QA 3주" 제거, 만화 배경 절반만 화면, 21일 안이 기각된 이유 포함. 경고 문구에 "무엇이 어긋났는지"를 실어 주자 모델이 실제로 고침.
- 관찰: 실행 중 `gemini-3.8/3.7-flash` 503, `3.6-flash` 분당 한도 429, `3.5-flash` 503 → `2.5-flash`까지 내려가며 완주. 폴백 없이는 무료 등급으로 서비스 불가. 한 실행 안에서 모델이 바뀌면 문체가 달라질 수 있음(미평가).
- **화면 읽기 (`engine/screens.py`)** ✔ 2026-09-18 — 키프레임 8장을 한 번의 호출로 읽음(약 1만 2천 토큰). Claude가 읽은 결과와 8장 중 6장 글자 완전 일치, 나머지 2장은 화살표 기호(`->`)와 깨진 아이콘 표기 차이뿐. 검증 오류가 난 프레임만 다시 읽히는 수리 단계 포함.
- **전사 (`engine/transcribe.py`)** ✔ 2026-09-18 — 오디오를 16kHz 모노 mp3로 줄여 8분 단위로 보냄. 4분 17초 강의: 호출 1회, 약 8천 토큰, **10초, GPU 불필요**. GPU Whisper와 본문 유사도 87%(차이는 대부분 표기 — Gemini는 `ETag`, `max-age`, `304 Not Modified`로 적고 Whisper는 "이 태그", "맥스 에이지"), 문장 시작 시각 차이 대체로 1초 이내, 말실수 "하루"를 그대로 받아적음. 전사 전용 모델 `gemini-3.5-transcribe`는 빈 응답을 돌려줘 Flash로 폴백됨(시스템 지침 칸을 받지 않는 모델은 지침을 사용자 메시지에 붙이도록 호출부 보강).
- **Gemini만으로 전 과정** ✔ — 같은 강의 영상에서 화면 읽기 → 전사 → 리포트(21항목) → 퀴즈(7문항) → 만화(8컷) → 모아보기까지 완주. 합계 호출 8회, 약 7만 2천 토큰, 2분 30초. `s-maxage`는 "슬라이드에만 있음", 1시간/하루 불일치는 별도 섹션, 퀴즈에서 제외.
- 미검증: 실제 사람 목소리(여러 화자, 잡음, 말 겹침), 8분 넘는 오디오의 조각 경계, 무음 구간에서의 지어내기, 하루 무료 한도(편수).
