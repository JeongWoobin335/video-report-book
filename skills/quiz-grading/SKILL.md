# 퀴즈 채점과 결과 분석

채점 자체는 스크립트가 한다. 이 스킬에서 당신이 할 일은 **숫자를 읽고 해석하는 것**이다. "4번 문항 정답률 33%"는 데이터일 뿐이고, 받아보는 사람에게 필요한 것은 "`no-cache`를 '캐시 안 함'으로 알고 있는 사람이 6명 중 4명입니다. 영상 04:20–05:35 구간이 이 오해를 풀지 못했습니다"라는 문장이다.

## 입력

작업 폴더에:
- `quiz.json` — comprehension-quiz 스킬의 결과 (정답·해설·다시 볼 구간 포함)
- `answers/*.json` — 응답. 한 사람당 한 파일:
  ```json
  {"respondent": "김하늘", "submitted_at": "2026-09-17T10:20:00", "answers": {"q1": "b", "q2": "d"}}
  ```

## 작업 흐름

### 1. 채점

```bash
python <이 스킬>/scripts/grade.py <작업 폴더>
```

`answers/`의 모든 응답을 채점해 `results/<응답자>.json`을 만든다. 각 결과에는 맞고 틀린 문항, 기억/이해별 정답 수, 그리고 **틀린 문항들의 구간을 합친 "다시 볼 구간"**이 들어 있다(가까운 구간은 하나로 합쳐서 "이 세 구간, 총 2분 10초만 다시 보세요"가 되게 한다). 응답하지 않은 문항은 틀린 것으로 센다.

한 사람의 결과만 필요하면 여기서 끝이다. 그 사람에게 결과를 전할 때는 점수보다 다시 볼 구간을 앞세운다.

### 2. 집계

```bash
python <이 스킬>/scripts/summarize.py <작업 폴더>
```

`summary.json`이 나온다: 문항별 정답률과 **보기별 선택 분포**, 소주제별·기억/이해별 정답률, 많이 틀린 구간, 그리고 스크립트가 찾은 신호(`flags`).

### 3. 해석 — `insights.md` 작성

`summary.json`과 `quiz.json`을 함께 읽고 `references/reading-results.md`의 방법대로 해석한다. 핵심은 많이 틀린 문항마다 **"영상의 문제인가, 문항의 문제인가"**를 가리는 것이고, 그 단서는 정답률이 아니라 **어떤 오답에 몰렸는가**에 있다.

```markdown
## 발견
- **무엇이 관찰됐는지 한 문장.** 근거가 되는 수치. → 권하는 조치. [mm:ss–mm:ss]
```

발견은 3~5개. 받아보는 사람이 월요일 아침에 뭘 하면 되는지 알 수 있게 쓴다. 응답자가 5명 미만이면 맨 위에 "응답 수가 적어 경향으로만 봐 주세요"를 밝힌다.

### 4. 결과 페이지

```bash
python <이 스킬>/scripts/summarize.py <작업 폴더>
```

같은 명령을 다시 돌리면 `insights.md`를 포함해 `summary.html`을 만든다. 템플릿은 `assets/summary-template.html`.

### 5. 사용자에게 보고

가장 중요한 발견 한두 개를 먼저 말하고, 파일 위치를 알린다.

## 회의 퀴즈일 때

`quiz.json`의 `type`이 `meeting`이면 결과의 성격이 다르다. 이것은 성적이 아니라 **팀의 인식이 어디서 어긋나 있는지**의 지도다.

- 개인별 순위나 점수표를 만들지 않는다. `summary.html`도 회의용은 개인별 표를 빼고 만든다. 누가 틀렸는지가 아니라 **무엇이** 잘못 전달됐는지를 본다.
- 발견은 "~를 틀렸다"가 아니라 "~로 알고 있는 분이 N명"으로 쓴다. 예: "출시일을 10월 21일로 알고 있는 분이 5명 중 2명입니다. 21일은 회의 중에 제안됐다 기각된 날짜입니다."
- 조치는 재시청 권유보다 **공지**다. "출시일이 28일로 확정됐다는 점을 채널에 한 번 더 공지하시길 권합니다."
