# 문항 쓰는 법

## 질문

**하나만 묻는다.** "A는 무엇이고 왜 그런가요?"는 두 문제다. 틀렸을 때 어느 쪽을 몰랐는지 알 수 없다.

**영상의 문장을 그대로 빈칸으로 만들지 않는다.** "캐시는 한 번 받아온 응답의 ___을 저장하는 것"은 단어를 기억하는지만 본다. 같은 내용을 다른 말로 묻는다: "캐시가 서버의 부하를 줄여주는 이유는 무엇인가요?"

**부정형은 피한다.** "~이 아닌 것은?"은 읽는 사람이 실수하기 쉽고, 오답 세 개가 모두 참이어야 해서 보기를 억지로 만들게 된다. 꼭 필요하면 "아닌"을 굵게 쓴다.

**질문만 읽어도 무엇을 묻는지 알 수 있어야 한다.** "다음 중 옳은 것은?"은 보기 네 개를 다 읽어야 문제가 뭔지 알 수 있다.

**영상에 의존하는 표현을 쓴다.** 일반 상식과 영상의 설명이 다를 수 있다. "이 강의에서는 ~를 무엇이라고 설명했나요?", "이번 회의에서 ~는 어떻게 정해졌나요?"처럼 기준이 영상임을 밝히면 정답 시비가 없다. 다만 모든 문항에 기계적으로 붙이면 거슬리므로 필요한 곳에만.

## 오답 보기 — 여기서 품질이 갈린다

오답은 **영상을 안 본 사람에게는 그럴듯하고, 본 사람에게는 분명히 틀린** 것이어야 한다. 재료는 이 순서로 찾는다:

1. **영상에 실제로 나온 다른 것.** `no-store`를 묻는 문항의 최고의 오답은 `no-cache`의 설명이다. 회의에서 최종 결정이 10월 28일이면 최고의 오답은 중간에 제안됐다 기각된 10월 21일과 원래 계획이던 10월 14일이다. 영상을 흘려 본 사람이 정확히 이런 데서 틀린다.
2. **영상이 직접 짚은 흔한 오해.** 강사가 "많이들 ~라고 착각하시는데"라고 한 내용은 그대로 오답이 된다.
3. **같은 범주의 그럴듯한 것.** 위 둘로 세 개가 안 채워질 때만. 날짜를 묻는데 보기가 모자라면 같은 달의 다른 날짜, 담당자를 묻는데 모자라면 회의에 나온 다른 참석자.

피해야 할 오답:
- **터무니없는 것.** "브라우저를 재시작합니다" 같은 보기는 없는 것과 같다. 사실상 3지선다, 2지선다가 된다.
- **"위의 모두", "정답 없음".** 내용을 몰라도 요령으로 풀 수 있게 된다.
- **정답만 길고 자세한 것.** 사람은 가장 길고 조건이 많이 붙은 보기를 고르는 경향이 있다. 네 보기의 길이와 구체성을 비슷하게 맞춘다. 정답을 줄이기 어려우면 오답을 늘린다.
- **정답과 사실상 같은 말.** 다 본 사람도 헷갈린다.
- **서로 겹치는 보기.** "1시간 이내"와 "30분"이 함께 있으면 둘 다 맞을 수 있다.

## 해설

해설은 틀린 사람이 읽는다. 정답이 왜 맞는지를 **영상이 말한 내용으로** 한두 문장 설명하고, 가장 많이 고를 법한 오답이 왜 틀렸는지 한 문장 덧붙인다. "정답은 2번입니다"만 쓰면 아무것도 배울 수 없다. 정답 번호는 쓰지 않는다 — 보기 순서는 나중에 섞인다.

## 좋은 예와 나쁜 예

> **나쁨** — 상식으로 풀린다
> 문제: 캐시를 사용하면 좋은 점은 무엇인가요?
> - [x] 속도가 빨라집니다 / [ ] 속도가 느려집니다 / [ ] 보안이 약해집니다 / [ ] 비용이 늘어납니다

> **좋음** — 영상의 구분을 이해해야 풀린다
> 문제: 새 버전을 배포하면 사용자가 곧바로 새 화면을 받아야 하는 HTML 문서에는, 이 강의에서 어떤 설정을 권했나요?
> - [ ] `max-age`를 1년으로 길게 줍니다 ← 영상에 나온 다른 권장값(해시 파일용)
> - [x] `no-cache`를 줍니다
> - [ ] `no-store`를 줍니다 ← 영상이 짚은 흔한 혼동
> - [ ] `max-age`를 1시간으로 줍니다 ← 영상의 예시에 나온 값

> **나쁨** — 영상을 다 본 사람도 답할 수 없다 (리포트에 없는 세부)
> 문제: 크래시 대시보드에서 검색 화면의 비중은 몇 퍼센트였나요?
> 사소한 숫자를 외웠는지는 이해와 상관이 없다. 숫자를 묻는다면 그 숫자가 논의의 핵심이었을 때만(출시일, 목표치).
