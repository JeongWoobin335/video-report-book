# 영상 리포트 파이프라인

이 스킬은 순서표다. 각 단계의 일은 그 단계의 스킬이 한다 — 단계에 들어갈 때 해당 스킬의 SKILL.md를 읽고 그대로 따른다. 여기서 요약해 둔 내용만 보고 진행하지 않는다(각 스킬에는 품질을 좌우하는 세부 지침이 있다).

스킬들은 이 스킬과 같은 폴더에 나란히 있다: `../video-ingest/`, `../speech-transcribe/` …

## 순서

| # | 단계 | 스킬 | 끝났다는 표시 | 필요한 것 |
|---|---|---|---|---|
| 1 | 영상 받아들이기 | `video-ingest` | `frames.json` | 영상 파일 |
| 2 | 음성 전사 | `speech-transcribe` | `transcript.json` | 1 |
| 3 | 화면 읽기 | `screen-read` | `screens.json` | 1 |
| 4 | 통합 리포트 | `integrated-report` | `report.json` | 2, 3 |
| 5 | 이해도 퀴즈 | `comprehension-quiz` | `quiz.json` | 4 |
| 6 | 만화 요약 | `comic-recap` | `comic.json` | 4 |
| 7 | 모아보기 페이지 | (이 스킬) | `index.html` | 4~6 |

`quiz-grading`은 여기 없다. 사람들이 퀴즈를 푼 **뒤에** 따로 쓰는 스킬이다.

## 진행하는 법

```bash
python <이 스킬>/scripts/status.py <작업 폴더>
```

어느 단계까지 끝났고 다음에 뭘 할 차례인지 알려준다. **새로 시작하든 이어서 하든 늘 이것부터 돌린다** — 판단 기준은 "끝났다는 표시" 파일이 있느냐 하나뿐이라, 중간에 끊겼던 작업도 같은 방식으로 이어진다. 작업 폴더가 아직 없으면 1단계부터다.

**2와 3은 동시에 한다.** 전사는 몇 분 걸리는 계산이고 화면 읽기는 당신이 직접 하는 일이다. 전사를 백그라운드로 시작해 놓고 그동안 화면을 읽는다. 마찬가지로 **5와 6도 서로 기다릴 필요가 없다.**

사용자가 일부만 원하면 그 부분까지만 한다. "회의록만"이면 4에서 멈추고, "퀴즈는 필요 없어"면 5를 건너뛴다. 사용자가 영상의 유형(회의/강의)을 말해줬으면 4단계에 그대로 전한다.

### 7. 모아보기 페이지

```bash
python <이 스킬>/scripts/make_index.py <작업 폴더>
```

만들어진 결과물(리포트, 퀴즈, 만화)로 가는 `index.html`을 만든다. 없는 결과물은 빼고 만든다.

## 다시 만들기

어떤 단계를 다시 하려면 그 단계의 결과물을 지우고 다시 진행한다. 앞 단계를 다시 하면 뒤 단계도 다시 해야 한다는 점에 주의한다 — 리포트를 고쳤으면(`report.json`이 바뀌었으면) 퀴즈와 만화는 옛 리포트의 항목 번호를 가리키고 있으므로 다시 만든다. `status.py`가 이런 경우를 "오래됨"으로 표시해 준다.

## 한 단계가 실패하면

그 단계에 기대지 않는 나머지는 계속한다. 만화가 실패해도 퀴즈는 만든다. 전사가 실패하면(오디오 손상 등) 화면만으로 리포트를 만들 수 있다 — `integrated-report`는 입력이 하나만 있어도 동작한다. 끝에 보고할 때 실패한 단계를 성공한 것처럼 말하지 않는다.

## 끝나고 보고할 것

1. `index.html`의 위치
2. 영상이 무엇에 관한 것이었는지 두세 문장
3. **사용자가 알아야 할 것들** — 각 단계가 보고하라고 한 한계를 모아서: 말과 화면이 어긋난 부분, 전사 품질이 나빴던 구간, 읽지 못한 화면, 담당자 없는 액션 아이템, 퀴즈·만화에서 제외한 내용과 이유
4. 실패하거나 건너뛴 단계
