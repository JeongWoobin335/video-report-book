# 영상 받아들이기

영상 한 편 = 작업 폴더 하나. 이 스킬은 그 폴더를 만들고, 뒤 단계(전사, 화면 읽기)가 쓸 재료를 준비한다. 내용을 해석하지는 않는다.

## 실행

```bash
python <이 스킬>/scripts/ingest.py <영상 파일> [--work <작업 폴더>] [--max-frames 40]
```

`--work`를 주지 않으면 `work/<영상 파일 이름>/`에 만든다. ffmpeg와 ffprobe가 PATH에 있어야 한다.

## 만들어지는 것

```
<작업 폴더>/
  video.<확장자>    원본의 복사본 (리포트 페이지가 이 파일을 재생한다)
  info.json        길이, 해상도, 오디오·비디오 트랙 유무
  audio.wav        16kHz 모노 — 전사 엔진이 바로 읽는 형식
  frames/0001.jpg  화면이 바뀐 지점의 키프레임
  frames.json      [{"time": 초, "image": "frames/0001.jpg"}, …]
```

## 키프레임을 고르는 방식 — 그리고 결과를 확인해야 하는 이유

모든 프레임을 읽는 것은 낭비다. 강의 영상은 10분에 슬라이드가 열 장쯤 바뀔 뿐이다. 스크립트는 ① 2초마다 한 장씩 작은 크기로 훑고 ② 직전에 채택한 프레임과 **그림이 충분히 달라졌을 때만** 채택하며 ③ 채택한 시각의 프레임을 원본 화질로 다시 뽑는다. 채택 기준은 지각 해시의 차이(`--threshold`, 기본 10)다.

끝나면 스크립트가 몇 장을 골랐는지 알려준다. **이 숫자를 영상의 성격과 견줘 본다:**

- 10분짜리 슬라이드 강의에서 40장(상한)이 나왔다 → 발표자 얼굴이나 커서 움직임에 반응한 것이다. `--threshold 14`로 올려 다시 돌린다.
- 화면 공유가 있는 30분 회의에서 3장이 나왔다 → 너무 둔하다. `--threshold 6`으로 내린다.
- 상한에 걸리면 스크립트는 변화가 작았던 것부터 버린다. 긴 영상이면 `--max-frames`를 늘린다(장당 화면 읽기 비용이 든다).

### 화면에 볼 것이 없는 영상

화면 공유 없는 화상회의 녹화(참가자 타일만 나옴), 정지 이미지 위에 음성만 있는 영상, 검은 화면. 이런 영상에서 키프레임이 1~3장 나오는 것은 **정상**이다. 첫 프레임을 열어 보면 바로 알 수 있다. 이때는 `--threshold`를 내리지 않는다 — 내려 봐야 압축 잡음과 발언자 표시의 깜빡임에 반응해 의미 없는 프레임만 쏟아진다. 그대로 다음 단계로 넘어가면 된다.

## 특수한 경우

- **오디오 트랙이 없다** → `audio.wav`를 만들지 않고 `info.json`에 `has_audio: false`. 뒤 단계는 화면만으로 진행한다.
- **비디오 트랙이 없다(음성 파일)** → 키프레임 없이 `frames.json`은 빈 목록. 뒤 단계는 음성만으로 진행한다.
- **같은 폴더에 다시 실행** → 이미 있는 `audio.wav`와 `frames/`를 덮어쓴다. 전사나 리포트 같은 뒤 단계의 결과물은 건드리지 않는다. **전사가 돌고 있는 중에는 같은 폴더에 다시 돌리지 않는다**(읽고 있는 `audio.wav`를 덮어쓴다). 키프레임 설정만 바꿔 다시 뽑을 땐 `--frames-only`를 주고, 여러 설정을 시험해 볼 땐 `--work`로 다른 폴더를 준다.
