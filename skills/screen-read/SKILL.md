# 화면 읽기

영상의 절반은 화면에 있다. 강사가 "여기 보시면"이라고 할 때의 "여기", 회의에서 "이 수치가"라고 할 때의 "이 수치"는 전사에 없다. 이 스킬은 키프레임을 **당신이 직접 눈으로 보고** 그 정보를 글로 옮긴다.

## 작업 흐름

### 1. 프레임 목록 확인

`frames.json`을 읽는다: `[{"time": 초, "image": "frames/0001.jpg"}, …]`

### 2. 프레임을 하나씩 본다

이미지 파일을 Read 도구로 연다(이미지를 볼 수 있다). 한 장씩, 순서대로. 여러 장을 한꺼번에 떠올려 쓰면 슬라이드 간에 내용이 섞인다.

프레임마다 세 가지를 적는다:

- **종류** — `slide`(발표 자료) / `screen_share`(앱, 문서, 대시보드, 코드 편집기 등 화면 공유) / `whiteboard`(판서) / `demo`(제품 시연) / `people`(사람의 모습만 보임) / `participants`(화상회의의 참가자 타일 — 프로필 그림, 이름표, 꺼진 카메라. 사람 얼굴이 안 보여도 여기에 넣는다) / `other`
- **글자** — 화면에 보이는 글자를 **그대로**. 아래 "글자를 옮기는 법" 참고.
- **설명** — 글자로는 안 담기는 것을 한두 문장으로: 도식이 무엇을 나타내는지, 그래프의 모양과 추세, 표의 구조, 강조 표시(빨간 동그라미, 화살표)가 어디를 가리키는지.

### 3. `screens-draft.md` 작성

```markdown
## 0001 | slide
글자:
HTTP 캐싱 기초
웹 성능 입문 3강
설명: 강의 제목 슬라이드.

## 0002 | people
설명: 화상회의 갤러리 화면. 참가자 세 명.

## 0003 | 0002와 같음
```

- 제목의 번호는 프레임 파일 이름의 번호. **모든 프레임에 대해 하나씩** 쓴다.
- 직전 프레임과 내용이 사실상 같으면(커서만 움직였다, 발표자 영상만 달라졌다) `## 0003 | 0002와 같음` 한 줄로 끝낸다. 스크립트가 합쳐 준다.
- 슬라이드에 항목이 하나씩 나타나는 애니메이션이면, 같은 슬라이드라도 **내용이 늘었으므로** 따로 적는다(뒤의 것에 전체 글자를 적는다).

### 4. 빌드

```bash
python <이 스킬>/scripts/build_screens.py <작업 폴더>
```

빠뜨린 프레임이 없는지 검사하고, "같음"으로 표시한 것을 합쳐서 `screens.json`을 만든다.

## 글자를 옮기는 법

**보이는 대로 옮긴다.** 오타처럼 보여도 고치지 않고, 줄 바꿈과 목록 구조를 살린다. 리포트 단계는 화면의 표기를 전사보다 신뢰하므로(고유명사, 숫자, 영어 용어), 여기서의 정확도가 리포트 전체의 정확도를 정한다.

- **표**는 행마다 한 줄, 칸은 공백 두 칸이나 `|`로 구분한다.
- **코드**는 들여쓰기까지 그대로.
- **그래프·차트**는 제목, 축 이름, 범례, 읽을 수 있는 수치를 글자에 적고, 모양("3월부터 급증")은 설명에 적는다. 눈금에서 어림한 값은 "약"을 붙인다.
- **안 읽히는 글자**는 지어내지 않는다. 작거나 흐려서 못 읽은 부분은 `[읽을 수 없음]`으로 표시한다. 그럴듯하게 메운 숫자 하나가 회의록의 틀린 결정 사항이 된다. 글꼴이 깨져 빈 네모(□)로 보이는 기호나 아이콘도 같은 표시를 쓰되, 설명에 "강조 아이콘으로 보이는 기호가 깨져 있음"처럼 사유를 적는다.
- 화면 공유에서 **내용과 무관한 것**(브라우저 탭, 메뉴 바, 시계, 알림)은 옮기지 않는다.

## 사람이 나온 화면, 참가자 타일

`people`과 `participants` 프레임은 리포트의 썸네일과 만화의 배경으로 쓰이지 않는다(실제 사람의 얼굴과 이름이 결과물에 박혀 돌아다니지 않게). 그러니 **내용이 있는 화면을 이 둘로 분류하지 않도록** 주의한다 — 화면 공유 옆에 작게 참가자 영상이 붙어 있는 것은 `screen_share`다.

`participants` 프레임은 글자에 보이는 이름표를 옮기고("이름표: 박상훈"), 설명은 "화상회의 참가자 타일, 공유 자료 없음" 정도로 쓴다. 영상 전체가 이런 화면이면 첫 프레임만 적고 나머지는 모두 `같음`으로 둔다 — 발언자에 따라 타일이 바뀌는 것은 내용의 변화가 아니다.

`people` 프레임은 "발표자 영상", "화상회의 갤러리, 참가자 네 명" 정도로만 설명한다. **얼굴로 누구인지 짐작하지 않고, 외모를 묘사하지 않는다.** 화면에 이름표(화상회의의 참가자 이름 표시)가 글자로 보이면 그것은 글자이므로 옮겨도 된다.

## 프레임이 없을 때

`frames.json`이 빈 목록이면(음성 파일) `{"screens": []}`를 쓰고 끝난다.
