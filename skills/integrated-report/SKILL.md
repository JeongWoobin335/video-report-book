# 통합 리포트

영상을 안 본 사람이 이 리포트만 읽고도 **무슨 일이 있었는지 알고, 미심쩍으면 해당 구간을 바로 찾아가 확인할 수 있게** 하는 것이 목표다. 그래서 두 가지가 핵심이다: 말과 화면을 **합쳐서** 읽는 것, 그리고 모든 항목에 **타임스탬프**를 다는 것.

이 리포트는 뒤에 퀴즈와 만화의 원천이 된다. 여기에 틀린 내용이 들어가면 퀴즈의 정답이 틀리게 되므로, 그럴듯한 추측보다 확인 가능한 사실만 쓰는 편이 낫다.

## 입력

작업 폴더(한 영상 = 한 폴더)에 아래 파일이 있다. 둘 중 하나만 있어도 된다.

- `transcript.json` — `{"duration": 초, "segments": [{"start", "end", "text", "speaker"}]}`
- `screens.json` — `{"screens": [{"time", "kind", "text", "description", "image"}]}`. `text`는 화면에 보이는 글자, `description`은 화면이 무엇인지에 대한 설명.

## 작업 흐름

### 1. 타임라인 만들기

```bash
python <이 스킬>/scripts/merge_timeline.py <작업 폴더>
```

`timeline.md`가 생긴다. "이 화면이 떠 있는 동안 이런 말을 했다"를 시간순으로 묶은 문서다. 전사와 화면을 따로 읽으면 "이 부분"이 뭘 가리키는지, 슬라이드의 숫자와 말한 숫자가 같은지 놓치게 되므로 반드시 이 합쳐진 문서를 기준으로 읽는다. 끝까지 다 읽고 나서 쓰기 시작한다 — 회의는 뒤에서 앞의 결정을 뒤집는 일이 흔하다.

### 2. 영상 유형을 정하고 해당 형식 가이드 하나만 읽기

| 유형 | 이런 영상 | 읽을 파일 |
|---|---|---|
| meeting | 여러 사람이 주고받으며 안건을 논의하고 뭔가를 정한다 | `references/meeting-report.md` |
| education | 한 사람이 주로 설명한다. 개념, 예시, 단계가 있다 | `references/education-report.md` |
| general | 위 둘이 아니다 (데모, 인터뷰, 발표, 대담 등) | `references/general-report.md` |

사용자가 유형을 말해줬으면 그대로 따른다. 애매하면 general로 간다 — 회의가 아닌 것을 회의록 틀에 넣으면 "결정 사항" 같은 칸을 억지로 채우게 된다.

### 3. `draft.md` 작성

형식 가이드의 구조를 따르되, 근거를 다는 방법은 `references/evidence-rules.md`를 따른다. 처음 한 번은 꼭 읽는다. 요점만 말하면:

- 본문의 모든 항목(불릿, 표의 행)에 `[mm:ss]` 또는 `[mm:ss–mm:ss]`를 단다.
- 나란히 비교하는 내용과 액션 아이템은 표로, 나머지는 불릿으로 쓴다. 같은 내용을 두 섹션에 반복하지 않는다.
- 영상에 없는 내용은 보태지 않는다. 배경지식으로 보충하고 싶어도 참는다.
- 말과 화면이 서로 다르면 어느 한쪽으로 정리하지 말고 둘 다 적어 따로 모은다.
- 충분히 자세하게 쓴다 — 화면·화제가 바뀔 때마다 항목 두세 개 이상, 주장과 이유·설명과 예시는 나눠서. 분량 기준은 `evidence-rules.md`의 "분량 감각".
- 채울 내용이 없는 섹션은 비워 두지 말고 통째로 뺀다.
- 본편 밖의 사담·뒷이야기는 넣지 않는다. 한 번만 들린 숫자·이름에는 `(확인 필요)`를 붙인다. (둘 다 `evidence-rules.md`에 기준이 있다 — 실제 녹화본에서 가장 사고가 나기 쉬운 부분이다.)

### 4. 근거 점검

```bash
python <이 스킬>/scripts/check_report.py <작업 폴더>
```

형식 오류(타임스탬프 없는 항목, 영상 길이를 벗어난 시각)를 잡아주고, `evidence.md`에 **각 항목과 그 시각의 실제 발화·화면을 나란히** 뽑아준다. 이 파일을 읽으며 항목마다 "원문이 정말 이 말을 하고 있는가"를 확인하고, 아니면 고치거나 지운다. 이 단계가 리포트의 신뢰도를 만든다. 오류가 0이 될 때까지 반복한다.

### 5. 렌더링

```bash
python <이 스킬>/scripts/render.py <작업 폴더>
```

`report.html`(사람이 읽는 독립 문서 — 영상은 담지 않으며, 그대로 인쇄하거나 PDF로 저장할 수 있다. 영상과 나란히 보는 화면은 파이프라인의 `watch.html`이 맡는다)과 `report.json`(웹 앱·퀴즈·만화가 읽는 구조화 데이터)이 나온다. 템플릿은 `assets/report-template.html`. 내용을 고칠 땐 `draft.md`만 고치고 다시 렌더링한다.

### 6. 사용자에게 보고

리포트 위치, 판단한 유형, 그리고 **사용자가 알아야 할 한계**를 짧게 알린다 — 리포트에서 뺀 본편 밖 구간(시각과 성격만), `(확인 필요)`로 표시한 숫자·이름, 전사 품질이 나빠 못 쓴 구간, 말과 화면이 어긋난 부분, 담당자·기한이 안 나와 비워둔 액션 아이템 등.

## 긴 영상

`timeline.md`가 한 번에 읽기 버거울 만큼 길면(대략 1시간 이상), 20분 단위로 끊어 구간별 메모(타임스탬프 포함)를 먼저 만들고 그 메모로 전체를 쓴다. 메모 단계에서 타임스탬프를 잃어버리면 나중에 되찾을 수 없으니 처음부터 달아 둔다.
