HTTP 캐싱 기초

웹 성능의 기본인 HTTP 캐싱의 원리와 제어 방법을 다루는 강의다. 캐시를 활용해 사용자 페이지 로딩 속도를 높이고 서버 부하와 비용을 줄이는 원리를 설명한다. Cache-Control 헤더의 max-age, no-cache, no-store 설정과 ETag를 이용한 저장본 유효성 검증 방식을 학습하며, 실무에서 파일 유형별로 권장되는 캐싱 전략을 제시한다.

학습 목표

00:08
  • 응답 헤더만 보고도 리소스가 브라우저에서 어떻게 캐시될지 동작을 설명할 수 있다. 00:22

핵심 개념

00:3002:34
  • 캐시(Cache) — 한 번 받아온 응답의 복사본을 가까운 곳에 저장해 두었다가 같은 요청이 오면 서버까지 가지 않고 그 복사본을 돌려주는 것. 00:32
  • ETag — 서버가 리소스 내용에 붙이는 지문 같은 값으로, 내용이 한 글자라도 바뀌면 함께 변경되는 식별자. 02:41

내용 정리

캐시의 필요성

00:0000:30
  • 페이지를 열 때마다 매번 서버에서 새로 받는 것은 낭비다. 00:03
  • 사용자 관점 도입 이유: 페이지 로딩 속도가 빨라진다. 00:47
  • 서버 관점 도입 이유: 요청 수가 줄어들어 서버의 부하와 비용이 낮아진다. 00:47
  • 예시: 쇼핑몰 첫 화면의 로고처럼 몇 달에 한 번 바뀔까 말까 한 자원은 브라우저 디스크에 저장해 두고 다음 요청부터 재사용한다. 00:56–01:16

Cache-Control 헤더를 통한 캐시 제어

01:1801:52
  • 브라우저는 서버가 보내 주는 응답 헤더인 Cache-Control을 통해 저장본을 언제까지 쓸 수 있는지 확인한다. 01:23
  • max-age는 응답을 몇 초 동안 신선(fresh)한 것으로 볼지 초 단위로 지정하는 가장 중요한 값이다. 01:29
  • max-age 기간 동안 브라우저는 네트워크 요청을 보내지 않고 서버에 묻지도 않은 채 저장본을 그대로 쓴다. (→ 영상 속 자료와 발언이 다른 부분 참고) 01:43–01:48
  • 슬라이드에만 있음: s-maxage=N은 CDN이나 프록시와 같은 공유 캐시 전용 max-age 설정이다. 01:18

ETag를 이용한 저장본 유효성 검증

02:34
  • 1단계: 첫 요청 시 서버가 응답 본문과 함께 ETag를 브라우저에 내려준다. 02:52
  • 2단계: 재요청 시 검증이 필요해지면 브라우저가 If-None-Match 헤더에 기존 ETag 값을 담아 서버에 보낸다. 03:00
  • 3단계 (일치): 서버에서 리소스의 ETag가 동일하면 본문 없이 304 Not Modified만 응답하며, 브라우저는 가벼워진 응답을 확인하고 저장본을 쓴다. 03:11–03:20
  • 3단계 (불일치): 내용이 바뀌어 ETag가 다르면 서버는 200 OK 응답과 함께 새 본문 및 새 ETag를 내려준다. 03:26

실무 캐싱 전략

03:30
  • 예시: 파일 이름에 고유 해시가 들어가는 자바스크립트나 CSS 파일(app.3f9a1c.js)은 내용 변경 시 파일명이 바뀌므로 max-age=31536000(1년)으로 길게 준다. 03:31–03:40
  • 예시: index.html 문서는 새로 배포했을 때 사용자가 즉시 최신 버전을 받도록 Cache-Control: no-cache를 설정하는 것이 일반적이다. 03:45–03:50
